# 共識 confidence score 的結構：一致性項的分布（第 16 項階段 0，唯讀）

> 狀態：統計已完成，**未改寫 §4.2**。待作者審閱後再決定 §4.2 的措辭。

本文件回答兩個問題：(1) `confidence_score` 的「一致性」項（dist 與 n_supporting）在 15 個分析資料集上實際分布如何；(2) GSE221107 的單工具呼叫（0.22%）對 biomarker 排名是否有影響。

## 0. 方法與範圍

- 診斷工具：`scripts/consensus_filter.py --dump-dist <tsv>`。預設關閉；不帶此旗標時輸出與原本逐位元相同（已在 7 個資料集以 byte 比對驗證，見第 4 節）。診斷資料直接取自 `vote()` 本身的比對結果，沒有另外寫座標比對邏輯。
- 每列為一個共識 locus，欄位：`n_supporting`、`bsj_ciriquant`、`dist_ciriquant`、`bsj_dcc`、`dist_dcc`、`confidence_score`。只計入會進入已發表共識的 locus（`confidence_score` 非 NA）。
- CIRIquant 與 DCC 的距離分開報告。CIRIquant 座標通常是 cluster 代表，所以 `dist_ciriquant` 幾乎恆為 0；**例外 2 個 locus**（GSE113230 chr14:20811288-20811446，SRR7012367 與 SRR7012370）：代表座標是 DCC 的，`dist_ciriquant` = 10（見第 2 節）。
- 統計腳本：`audit/confidence_structure_stats.py`。執行方式：
  ```
  python audit/confidence_structure_stats.py <root> <out.md> <fig.png>            # 現行程式的 dump（目錄 dump/）
  python audit/confidence_structure_stats.py <root> <out.md> <fig.png> dump_pre  # 去重前程式的 dump（目錄 dump_pre/）
  ```
  腳本會略過 `*_s.tsv`（與 dump 並存的 consensus summary，不是 locus 資料）。第一次執行去重前版本時，這些 summary 被算進去，導致 locus 數變成兩倍，n=2 比例顯示 0.5；本文件使用修正後的結果。
- 產出的統計表與圖（`stats2_*.md`、`fig2_*.png`）留在伺服器 scratch（`~/item16/`），依慣例不納入 git。

## 1. 判讀規則（事前寫定，統計前已寫入腳本）

- 若 DCC 支持的 locus 中 `dist_dcc = 0` 的比例 ≥ 90%，且兩工具 locus 的 Spearman ρ（confidence_score 對 log2(bsj+1) 平均項）≥ 0.99，判為 **STRUCTURAL**：一致性項幾乎為常數。
- 若 `dist_dcc = 0` 比例 < 90%，判為 **EMPIRICAL**：一致性項有變異，但仍需看 ρ 才能判斷它是否有資訊量。
- 其他情況判為 **INTERMEDIATE**，如實報告，不歸入任一邊。

## 2. 結果（現行程式，15 個資料集，628,793 個共識 locus）

判定：**STRUCTURAL**（dist_dcc = 0 比例 0.999 ≥ 0.90；ρ = 0.9995 ≥ 0.99）。

| 資料集 | locus 數 | dist_dcc = 0 | dist_dcc 1–3 | dist_dcc 4–10 | ρ（2 工具 locus）|
|---|---:|---:|---:|---:|---:|
| 全部 | 628,793 | 0.999 | 0.001 | 0.001 | 0.9995 |
| GSE108735 | 19,922 | 0.999 | 0.000 | 0.000 | 0.9997 |
| GSE113230 | 79,052 | 0.998 | 0.001 | 0.001 | 0.9991 |
| GSE121842 | 17,492 | 0.999 | 0.001 | 0.001 | 0.9996 |
| GSE130078 | 20,817 | 0.998 | 0.001 | 0.001 | 0.9995 |
| GSE133998 | 40,444 | 1.000 | 0.000 | 0.000 | 0.9998 |
| GSE136569 | 173,037 | 0.999 | 0.000 | 0.001 | 0.9997 |
| GSE143797 | 15,439 | 0.999 | 0.000 | 0.000 | 0.9998 |
| GSE148036 | 1,197 | 0.999 | 0.001 | 0.000 | 0.9989 |
| GSE171011 | 68,317 | 0.999 | 0.000 | 0.000 | 0.9998 |
| GSE221107 | 34,460 | 0.998 | 0.001 | 0.001 | 0.9991 |
| GSE248612 | 30,410 | 0.999 | 0.000 | 0.001 | 0.9988 |
| GSE77509 | 9,832 | 0.999 | 0.001 | 0.001 | 0.9992 |
| GSE97239 | 40,375 | 0.998 | 0.001 | 0.001 | 0.9992 |
| PRJNA553289 | 37,446 | 0.999 | 0.000 | 0.000 | 0.9991 |
| SRP156355 | 40,553 | 0.998 | 0.001 | 0.001 | 0.9994 |

- n_supporting：所有 locus 的 n_supporting 皆為 2（n=1 占 0）。原因：共識以 `min_tools=2` 產生，單工具 locus 不會進入已發表共識（GSE221107 的單工具列見第 4 節）。
- `dist_ciriquant`：628,791 個為 0，**2 個為 10**（dist 0 比例 0.999997，不是 1.000）。這 2 個 locus 的 `dist_dcc` = 0，代表座標取自 DCC。兩個 caller 座標不同的 locus 合計 796 個（0.13%）：794 個 `dist_dcc` > 0，加上這 2 個。
- **教訓**：三位小數四捨五入會把 0.9995 或 0.999997 顯示成 1.000，讓「有例外」讀成「完全一致」。同一形狀已使 §4.2 一度寫錯（v64 前）。報告這類比例時必須同時給絕對數。
- 一致性因子 f = 1 − dist_dcc/10 的平均值 0.9995，變異係數 CV = 0.016（全部 locus）。各資料集 CV 介於 0.008（GSE133998）與 0.022（GSE221107）。

**解讀注意**：dist_dcc = 0 的意思是 DCC 座標與所選代表（CIRIquant 座標）完全相同，而非「在 slop 範圍內相符」。因此「一致性項近乎為常數」的實際機制是：兩工具在 99.9% 的 locus 上給出完全相同的座標。這是事實，但它來自精確座標一致，不是 slop 容忍的設計效果。§4.2 若要寫「一致性項不提供資訊」，應說明這一點。

## 3. 去重前程式版本（commit 4dfa28a^）

判定同為 **STRUCTURAL**（dist_dcc = 0 比例 0.998；ρ = 0.9977）。資料集：GSE121842、GSE130078、GSE148036、GSE221107、GSE248612、GSE77509、PRJNA553289、SRP156355（共 193,362 個 locus；n=2 占 100%）。

## 5. GSE221107 單工具呼叫（0.22%）：未重現於分析子集

- 已發表 `consensus_summary.tsv` 中，GSE221107 的 n_tools = 1 共 86 列，全部位於 **SRR22757419（73 列）與 SRR22757422（13 列）**。這兩個樣本正是被排除的降解樣本（Pair 11 normal、Pair 8 normal），其 adaptive fallback 使 min_tools 降為 1。86 / 39,681 ≈ 0.22%，與資料表的數字吻合。
- 保留的 8 個樣本（SRR22757410/412/414/416/430/432/434/436）的 n_tools = 1 列數為 **0**。
- 因此「0.22% 單工具」是被排除樣本的現象，**不影響分析所用的 8 個樣本**。

### 半衰減實驗：未執行

原計畫把 GSE221107 的單工具 locus 分數減半後重算 biomarker 排名。目標 locus 在分析子集中數量為 0，所以排名預期不會改變（no-op）。我沒有執行這個實驗，因為它只有在把被排除的樣本重新納入時才有意義；若需要，可另行在 scratch 進行，並明確標註該結果使用了被排除樣本。

## 6. 限制

- 統計只涵蓋「已進入共識」的 locus。被最小工具數門檻過濾掉的 locus 不在 dump 中，因此 n=1 的分布只反映已發表共識的結構，不反映偵測原始資料。
- dump 的資料集名稱由輸出路徑推得（`dump_pre` 與 `dump` 的目錄結構不同，由腳本從 dump 檔案路徑取得）。
- 去重前版本的 dump 是以修補過 `--dump-dist` 的副本產生，其預設輸出是否與原始去重前程式逐位元相同，未單獨驗證（僅驗證了 locus 集合）。
